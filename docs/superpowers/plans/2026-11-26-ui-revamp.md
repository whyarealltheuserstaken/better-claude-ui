# UI and UX Revamp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the look and navigation of BetterClaudeUI (approved "Glass" look plus a right-hand panel), add a customizable usage widget and a tray version.

**Architecture:** Shared design system first (derived theme colors, icons, shared controls), then the shell, then each screen, then the widget and tray. Decisions live in small pure TypeScript modules with tests; Svelte components render them. Rust changes are limited to new settings, token-usage events and the tray.

**Tech Stack:** Tauri v2, Rust, SvelteKit / Svelte 5, Vitest, playwright-core (screenshots through installed Edge).

**Spec:** `docs/superpowers/specs/2026-11-26-ui-revamp-design.md`

## Global Constraints

- Text contrast at least 4.5:1 on the worst-case composited background. Default text at least 13px, nothing below 11px.
- Click targets at least 28×28px by default, never under 20×20px.
- Glass only on the floating layer (sidebar, right panel, toolbar controls, composer, permission prompt, menus, floating widget, tray panel). Page content is solid.
- `gate` is reserved for waiting. Color is never the only waiting signal. No looping background animation.
- Honor `prefers-reduced-motion`, `prefers-reduced-transparency`, `prefers-contrast: more`, forced colors. No in-app duplicates.
- Standard OS window frame. Production CSP unchanged. No Apple fonts or SF Symbols. Icons: Lucide (ISC), only used paths, license noted.
- Tier gating (`capsFor`) applies everywhere a control appears. Bypass keeps its confirmation everywhere.
- No feature may disappear or get harder to reach.
- Saved theme format (12 colors) unchanged; saved custom colors are never edited.
- New config fields have defaults so old `config.json` files load.
- No release, no `v*` tag. No attribution lines in commits or PR bodies. Commit identity stays the repo-local noreply address.
- One PR per stage; squash-merge when CI is green; each PR updates `docs/PROGRESS.md`.
- E2E safety rules in `docs/HANDOFF.md` 10i: never delete anything the test did not create.

## Review Focus

1. A custom or imported theme with unreadable colors (text equal to background): the app stays readable and the saved colors are unchanged. (Task 1)
2. An old `config.json`, or garbage in the widget or tray settings: loads with defaults, never a blank widget or crash. (Tasks 4, 14)
3. A 720×480 window: Deny / Always allow / Allow and Send stay visible and usable; the right panel gets out of the way. (Tasks 5, 7; screenshots)
4. A permission request while the user is on another page, another session, or the window is hidden: a badge or tray state shows it and nothing takes focus onto Allow. (Tasks 4, 7, 16)
5. Token events with missing fields, subagent steps, or repeated cumulative counts: never NaN, never double counted. (Task 13)

## Common verification

"Verify" in each task means: `npm run check` (0 errors) and `npm test` (all pass). Tasks that touch Rust also run:
`cargo fmt --manifest-path src-tauri/Cargo.toml --check`,
`cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --features test-support -- -D warnings`,
`cargo test --manifest-path src-tauri/Cargo.toml --features test-support`.

Each task is test first: write the tests listed, run them and see them fail, implement, Verify, commit.

## Stage 1: Design system (PR 1)

### Task 1: Color maths and derived theme colors
**Files:** Create `src/lib/color.ts`, `src/lib/color.test.ts`. Modify `src/lib/theme.ts`, `src/lib/theme.test.ts`.

**Interfaces (produces):**
- `contrast(a: string, b: string): number`; `mix(a: string, b: string, t: number): string` (t=0 gives a); `ensureContrast(fg: string, bgs: string[], min?: number): string` returns `fg` if it already passes on every background, otherwise `fg` moved toward black or white just far enough (all 6-digit hex).
- `deriveColors(theme: Theme): Derived` in `theme.ts`: `{ solid: boolean; neutralGlow: boolean; text, muted, accentInk, gateInk, accentText, gateText, okText, badText, sheet, card, glassBase: string; glassAlpha: number; backgrounds: string[]; glow: [string,string,string]; wait: [string,string] }`. `backgrounds` lists every worst-case composited surface text can sit on.
- `adjustedKeys(theme: Theme): (keyof ThemeColors)[]`: which saved colors are shown adjusted (for the editor note).
- `appearanceVars` additionally sets `--sheet --card --glass --accent-text --gate-text --ok-text --bad-text --glow-a --glow-b --glow-c --wait-a --wait-b`; `--text --muted --accent-ink --gate-ink` carry derived values. `applyAppearance` sets `root.dataset.solid` and `root.dataset.scheme`.

**Tests:**
- `contrast("#000000","#ffffff")` is 21; `contrast("#777777","#777777")` is 1.
- `ensureContrast("#93a1a1",["#fdf6e3"])` has contrast ≥ 4.5; a passing color is returned unchanged.
- For every built-in theme: `text`, `muted`, `accentText`, `gateText`, `okText`, `badText` ≥ 4.5 on every entry of `backgrounds`; `accentInk` on `accent` and `gateInk` on `gate` ≥ 4.5.
- A custom theme with `text` = `bg` derives readable text, `theme.colors` stays deep-equal to its input, and `adjustedKeys` includes `"text"`.
- `high-contrast`: `solid` true. `terminal-amber` and `high-contrast`: `neutralGlow` true. `graphite`: false.
